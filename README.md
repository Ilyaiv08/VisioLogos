# VisioLogos

Программа для вывода текстов, песен и презентаций на проектор во время
церковных служений.

Главный принцип: то, что оператор делает у себя, зал не видит, пока он сам
это не отправит. Слева «Подготовка», справа «Окно слайда» — то, что прямо
сейчас на проекторе. Отправить можно кнопкой «Показать», пробелом или двойным
кликом по стиху.

## Запуск

```bash
npm install
npm run dev
```

Собрать установщик для Windows:

```bash
npm run dist
```

Проверить парсер модулей и раскладку по слайдам без запуска программы:

```bash
npm run check
```

## Установщики

```bash
npm run dist        # Windows: установщик и переносная версия
npm run dist:mac    # macOS: .dmg и .zip — только на самом маке
```

**Windows.** Собираются два файла: `VisioLogos-<версия>-setup.exe` —
обычный установщик, и `VisioLogos-<версия>-portable.exe` — та же
программа одним файлом, без установки. Установщик ставит программу в папку
пользователя, а не в `Program Files`: тогда он не просит прав
администратора, которых на приходском компьютере обычно нет. Русский язык
установщика, ярлыки на рабочем столе и в меню «Пуск», выбор папки — всё на месте.

**Песни при удалении остаются.** `deleteAppDataOnUninstall: false` —
программу сносят и ставят заново чаще, чем кажется, и стереть вместе с ней
библиотеку общины было бы бедой, которой никто не ждёт от кнопки «Удалить».

**macOS.** Собирается `.dmg` (перетащил в «Программы» — поставил)
и `.zip`, под Apple Silicon и под Intel. Собрать это на Windows
нельзя: electron-builder отвечает «Build for macOS is supported only on macOS».
Нужен мак — свой или в облаке.

Подписи Apple пока нет: она стоит денег и требует записи разработчика.
Пока её нет, при первом запуске macOS попросит открыть программу через
правую кнопку → «Открыть». Появится запись — в `package.json`
меняется одна строка (`mac.identity`).

## Что уже работает

**Вкладка «Библия»** — четыре колонки подряд (класс, книга, глава, стих), как
в VisioBible. Переключение переводов и режим двух переводов на одном слайде.

**Как выделять и выводить:**

| Действие | Что делает |
|---|---|
| Клик | Готовит слайд, зал ничего не видит |
| Двойной клик | Сразу выводит в зал |
| Протяжка мышью | Выделяет несколько стихов подряд; у края список подкручивается сам |
| Shift + клик | Расширяет выделение от уже выбранного |
| Правая кнопка | Меню: показать, добавить в план, выделить главу, скопировать |

Протяжка считает строку под курсором сама, а не по событиям наведения:
пока кнопка мыши зажата, браузер их не шлёт, и выделение обрывалось бы
на первой же строке.

**Модули Библии с сайта** — «+ Перевод» открывает список того, что лежит
на [visiologos.ru](https://visiologos.ru): триста с лишним переводов,
толкований, словарей и книг. Нажали «Поставить» — модуль скачался,
развернулся и появился в списке переводов. Раньше на это уходило шесть шагов:
открыть сайт, скачать архив, найти его в «Загрузках», распаковать, вернуться
в программу, указать папку.

Каталог берётся с сайта и держится полчаса в памяти. Доменов два, и второй
запасной: не ответил первый — спрашиваем второй, и человек этого не замечает.
Нет сети вовсе — окно честно говорит об этом и предлагает то, что работает
всегда: папку с диска.

Ничего постороннего не скачивается: адрес складывается из своего же домена
и имени модуля, а имя проверяется тем же выражением, что и на сервере.
Ссылку наружу открывает главный процесс и только на свой домен —
`isOurSite` в `src/shared/site.ts`, и это под самопроверкой.

Тот же список открывается из «Файл → Модули Библии с сайта…», а под списком
переводов стоит строка «Ещё переводы — на visiologos.ru».

**Книги по разделам** — цвет книги показывает раздел: Закон, Исторические,
Учительные, Большие и Малые пророки, Евангелия, Деяния, Соборные послания,
Послания Павла, Откровение. Между Заветами черта. Заголовков разделов
в списке нет намеренно: они занимали место, из-за которого в колонку
помещалось меньше книг, — название раздела показывается в подсказке при
наведении.

Раздел определяется по латинскому сокращению из модуля (`Ge`, `Ps`, `Mt`,
`Rev`), поэтому цвета не поедут на другом переводе.
Оттенки приглушены намеренно: насыщенный цвет в программе занят под эфир,
и книги не должны с ним спорить.

**Порядок книг один во всех переводах — синодальный.** Модули приходят
с разным: половина изданий ставит Послания Павла перед Соборными, и «Иакова»
оказывалось то сразу за «Деяниями», то в самом конце, смотря какой перевод
открыт. Оператор ищет книгу глазами и на память, посреди служения, — порядок
не должен меняться у него под руками. Список и раздел живут одной таблицей
(`src/shared/bookGroups.ts`): порознь они разъезжались, и «К Евреям»
числилось у Павла, а стояло среди Соборных.

Переставляется только то, что программа узнала целиком. Если хоть одна
книга модуля не отозвалась на латинское сокращение, порядок остаётся тем,
что задало издание: узнать половину и переставить её — значит перемешать
список сильнее, чем он был. Порядковые номера книг при этом не трогаются,
по ним программа читает главы.

**Неканонические книги живут своим списком.** В «Целой Библии» их нет:
у семидесятисемикнижных изданий они вставали хвостом сразу за «Откровением»,
и оператор, ведущий пальцем по списку до конца, упирался в Маккавейские
вместо Откровения. В переводе, где их нет вовсе, эта строка не показывается:
раньше она открывала пустой столбец и стояла в списке наравне с Заветами.

**План проповеди** — список мест по порядку с началом текста. Пополняется
правым меню на любом стихе, результате поиска или строке истории, либо
вставкой списка целиком («+ список»): `Ин 3:16; Рим 5:8, 10` разбирается
в три адреса. Порядок меняется перетаскиванием, показанные места помечаются
галочкой сами.

**Оформление слайда** — номера стихов, линейки над и под текстом, адрес в
углу («От Иоанна (Jn.) 1:16»), выбор шрифта, кегля, цвета и выключки.
Восемнадцать встроенных фонов сделаны заливками: ничего не весят и не мылятся
на любом разрешении проектора. В галерее они разложены группами — «Тёмные»,
«Светлые» и «Свои», — иначе светлые начинались бы посреди строки, вперемешку
с тёмными. Тёмные для затемнённого зала (светлый экран там слепит), светлые
для комнаты с окнами, где тёмный слайд выглядит серым пятном.

«Бумага» и «Пергамент» — с настоящей бумажной текстурой: зерно, разводы
и тень по краям, как у раскрытой книги. Это тоже не картинка, а шум,
который считает сам браузер (фильтр SVG `feTurbulence`), — файла нет,
и на большом экране узор не рассыпается на пиксели.

Свои картинки и видео добавляются кнопкой
«Загрузить с компьютера» — файл копируется в папку программы, поэтому фон
не потеряется, если исходник удалят. Настроенный вид сохраняется как шаблон
и переживает перезапуск.

**Быстрый поиск** — одна строка на два случая. «Ин 3:16», «1 Кор. 13, 4»,
«От Иоанна 3:16» открывают стих сразу; «в начале было слово» ищет по всей
Библии (6–7 мс на полный проход по 31 162 стихам).

Название книги ищется сначала точно, потом по началу: модули называют книги
по-разному — в Синодальном это «От Иоанна», в Новом русском переводе
«От Иоанна святое благовествование», а набирают в обоих случаях одинаково.
Совпадение по началу принимается, только если оно единственное.

**Длинный текст** — программа сама уменьшает шрифт до заданного минимума, а если
и этого мало, режет текст на слайды. Оператор видит «слайд 1 из 2»
в предпросмотре заранее, а не на служении.

**Стих не разрывается между слайдами.** Не помещается вместе с предыдущими —
уезжает на следующий слайд целиком. Половина стиха внизу одного слайда
и вторая половина на другом читаются плохо. Делится только тот стих, который
не влезает на слайд даже в одиночку, — иначе его не показать вовсе.

Влезает или нет, решается **настоящим замером разметки**, а не прикидкой
по числу символов ([`fitTest.ts`](src/renderer/src/lib/fitTest.ts)). Прикидка
ошибалась процентов на пять: на слайд ставилось 1425 знаков там, где реально
помещалось около 1378, и хвост последнего стиха обрезался краем. Замер строит
ту же разметку, что и слайд, при опорной ширине 1920 — кегль задан в долях
от высоты, поля в процентах от ширины, поэтому результат одинаков и для
окошка предпросмотра, и для проектора. Второй перевод при замере тоже
учитывается: с ним на слайде вдвое больше текста.

**Подпись с адресом** в углу слайда должна читаться с задних рядов, поэтому
её размер задаётся отдельно — ползунком «Размер подписи» в долях от основного
кегля, по умолчанию 0,62. Вид выбирается там же:

| Вид | Как выглядит |
|---|---|
| `full` (по умолчанию) | От Иоанна 3:16 |
| `short` | Иоан. 3:16 |
| `latin` | От Иоанна (Jn.) 3:16 — для гостей с Библией на другом языке |

Латинское сокращение берётся из модуля, но цифра в начале за латинскую букву
не считается: иначе у «1-е Коринфянам» вместо `(1Co.)` подставлялось бы
русское `(1Кор.)`. Под неё резервируется место
снизу, и текст подгоняется уже в остаток: иначе крупная подпись наезжала бы
на последнюю строку. Резерв считается от заданного кегля, а не от подобранного,
чтобы раскладка не зависела от того, насколько ужался текст.

**Вывод в зал** — отдельное полноэкранное окно без единой кнопки на выбранном
мониторе. Фокус остаётся на пульте, поэтому пробел и стрелки продолжают
работать. Подробнее — в разделе [«Экраны»](#экраны).

### Вкладка «Тексты»

Объявления, цитаты и темы проповедей. Шесть заготовок: **Объявление**,
**Цитата** (с автором под текстом), **Тема проповеди** (крупно, прописными),
**Благодарности и нужды**, **Пустой слайд** (свободная раскладка)
и **Обратный отсчёт**.

Пустая строка в тексте начинает новый слайд — оператор сам решает, где разрыв.
Если кусок всё равно не влезает, он режется по предложениям тем же правилом,
что и длинные места Писания.

**Благодарности и нужды** — одна заготовка с двумя разделами: в церкви их
объявляют вместе, одним листком, и разводить их по разным текстам не за чем.
У каждого раздела свой заголовок и свои пункты; ненужный раздел можно оставить
пустым — на экран он не попадёт.

Одна строка равна одному пункту, и ничего больше набирать не надо. Метку
(«1.», «—», «•») программа ставит сама, а если список принесли уже
размеченным, чужую метку она снимает.

Пункты раскладываются по слайдам так, чтобы шрифт остался крупным: список
читают издалека, и лучше три слайда по четыре пункта, чем один, на котором
двенадцать строк мелким кеглем. Слайд набирается не «под завязку» — семь
пунктов лягут как четыре и три, а не как пять и два. Разделы не смешиваются:
нужды начинаются с нового слайда, даже если благодарности не дописаны до низа.

Заголовок раздела повторяется на всех его слайдах: вошедший в середине должен
понимать, о чём список. Нумерация, если она включена, идёт сквозь слайды
раздела и в следующем начинается заново.

Хранится всё это обычным текстом — заголовок с двоеточием, под ним пункты, —
поэтому список ищется по вкладке наравне с остальными текстами.

**Внизу слайда видно, кончился список или нет.** Пока пункты остались,
там стоит знак «▾ ещё 4 пункта»; на последнем слайде вместо него — черта
во всю ширину текста. Список из трёх слайдов выглядел раньше одинаково
на всех трёх, и зал не знал, дочитывать или уже молиться: молчание —
плохая подсказка. Знак считает оставшиеся пункты, а не слайды, — «ещё
2 слайда» человеку в зале не говорит ничего. Список из одного слайда
обходится без знаков вовсе: там и так всё видно, а лишняя черта — лишняя
строка на экране.

**Поле ввода растёт под текст.** Высота полей была задана раз и навсегда:
девяносто пикселей у раздела благодарностей, семьдесят у части песни. Пока
строк три, этого хватает. Но список нужд — это дюжина строк, и одиннадцать
из них оператор набирал вслепую, в окошко высотой в четыре строки: поправить
опечатку в середине такого списка — отдельная работа, сначала найди её
прокруткой, потом не потеряй.

Теперь поле подгоняется под написанное, а когда в нём работают — раскрывается
ещё и на пару строк запаса, чтобы под курсором оставалось место. Расти без
конца ему нельзя: панель прокручивается целиком, и поле в тысячу пикселей
увело бы за край и кнопку «Сохранить», и соседние настройки, — поэтому
у роста есть потолок в неполный экран, а дальше поле прокручивается внутри
себя, как раньше. Работает это во всех полях: разделы списка, части песни,
текст объявления, вставка плана проповеди.

Ползунок **«Пунктов на слайде»** нужен, когда за нужды молятся по очереди:
поставьте один пункт — и каждый будет висеть на экране отдельно.

**Пустой слайд** — единственное место, где программа не раскладывает ничего
сама. Строки набираются по одной, у каждой свой размер («мелко», «обычно»,
«крупно», «огромно»), порядок меняется стрелками. Текст ставится сверху,
по центру или снизу, а под него можно подложить плашку — тёмную или светлую,
чтобы читалось поверх пёстрой фотографии. Отдельной кнопкой добавляются часы:
до начала служения на экране чаще всего нужны две вещи — когда начнём
и сколько сейчас.

Слайд получается ровно один: что набрали, то и покажется. Пригодится там,
где нужное не похоже ни на объявление, ни на цитату, — имя новорождённого
во весь экран, «Тишина, идёт причастие», номер счёта для пожертвований.
Пока не набрано ни строки, на экране только фон: это прежний «Пустой слайд»,
и таким он остаётся, чтобы убрать текст, не гася проектор.

**Обратный отсчёт** хранится моментом окончания, а не остатком: зал, сцена
и пульт показывают одни и те же цифры, даже если окно вывода открыли посреди
отсчёта.

**Нижняя плашка** — полоса внизу поверх текущего слайда. Живёт отдельно от
слайда: короткое объявление появляется, не сбивая то, что читают в зале,
и убирается одной кнопкой.

**Текст выгружается в файл** — как песня: обычным текстом, в PDF или
в PowerPoint. Список молитвенных нужд чаще всего нужен не только на экране:
его отправляют тем, кто молится по средам дома, или печатают и раздают.
Раскладка при этом та же, что на проекторе, — по слайдам, с заголовками
разделов и нумерацией: лист в руках и слайд на стене должны совпадать.

У каждого текста может быть свой фон — заставка объявлений обычно отличается
от фона Писания. Тексты хранятся в `texts.json`, удалённое уезжает в корзину
на пятьдесят записей.

**Горячие клавиши** повторяют расположение кнопок в «Управлении»:

| Клавиша | Действие |
|---|---|
| `Пробел` | Дальше по служению: до конца текущего места, затем следующий стих |
| `←` `→` | Предыдущий и следующий стих |
| `↑` `↓` | Предыдущий и следующий слайд этого же места |
| `K` | Караоке: включить и выключить |
| `Enter` | Отметить строку спетой |
| `B` | Чёрный экран |
| `T` | Только фон |
| `Esc` | Очистить экран |

Шаг стрелками меняет зал, **только если там уже что-то есть**. При пустом
экране меняется одна подготовка: листая её, оператор не должен случайно
вывести что-то в зал. Пробел — наоборот, всегда показывает.

В полях ввода клавиши не перехватываются.

## Обновление

Новая версия ничего не стоит, пока она не у людей. Раньше это означало:
зайти на сайт, скачать сто с лишним мегабайт, найти файл в «Загрузках»,
пройти установщик. Половина операторов не делала этого никогда — и жила
со старыми ошибками, давно исправленными.

Теперь программа спрашивает сайт сама и, если есть что новее, показывает
кнопку «Обновить» рядом со знаком в верхней строке. Нажали — скачалось,
проверилось, поставилось поверх старой версии, программа открылась заново.
Служения, песни и настройки при этом не трогаются: они лежат в папке
данных, а установщик заменяет только саму программу.

Что здесь важно и почему сделано именно так:

* **спрашиваем тихо.** Один раз при запуске, с задержкой в шесть секунд —
  первые секунды программа занята библиотекой и окнами вывода, — и потом
  не чаще раза в сутки. Нет связи или сайт молчит — кнопки просто нет.
  Окно с извинениями вместо кнопки никому не помогает;
* **ставим только по нажатию.** Программа не обновляет себя сама и никогда
  не делает этого в тишине: обновление посреди служения недопустимо,
  а другого времени программа не знает. Если служение идёт, кнопка
  спрашивает второй раз — «точно?»;
* **проверяем, что скачалось.** Сайт отдаёт отпечаток файла (`sha256`
  в `/api/release`), программа считает свой и сверяет. Оборванная загрузка
  на медленном интернете — вещь обычная, а запускать наполовину скачанный
  установщик нельзя: он снесёт рабочую программу и не поставит новую,
  причём выяснится это перед служением;
* **имя файла с сайта проверяется** тем же выражением, что и на сервере:
  по этому имени называется файл на диске, который потом запускают. Сайт
  свой, но «своё» — это про то, кому мы доверяем, а не про то, что нельзя
  ошибиться;
* **установщик работает тихо** (`/S`) и ставится для одного пользователя,
  поэтому прав администратора не спрашивает. `--force-run` открывает
  программу заново, когда всё встало;
* **установщик переживает закрытие программы.** Раньше обновление
  доходило до половины: файл скачивался, программа закрывалась — и ничего
  не происходило. Установщик запускался её же процессом и умирал вместе
  с ним. Теперь он отвязывается от программы совсем (`detached`, потоки
  разорваны) и живёт дальше сам. А если запустить его всё-таки не вышло,
  программа не закрывается молча: говорит об этом и показывает скачанный
  файл в проводнике — поставить руками всегда можно.

Переносной версии кнопка честно говорит, что здесь обновиться нельзя:
она лежит там, куда её положили — на флешке, в «Загрузках», на рабочем
столе, — и установщик её не заменит. Вместо кнопки — ссылка на сайт.

В сеть программа ходит только через `net.fetch` — сетевой стек Chromium,
тот же, которым живёт окно. Обычный `fetch` из Node не знает ни системного
прокси, ни сертификатов, поставленных в систему: у человека с VPN сайт
открывался в браузере, а программа отвечала «нет связи с сайтом». Это
закреплено проверкой в `npm run check`, чтобы не вернулось.

## Оформление

Правила, на которые опираются все вкладки. Приёмы живут в
[`src/renderer/src/styles.css`](src/renderer/src/styles.css), краски —
в [`themes.css`](src/renderer/src/themes.css). В разметке цветов нет вовсе:
всё берётся из переменных, и стиль — это просто другой набор их значений.

**Три состояния — три разных приёма, а не три оттенка:**

| Состояние | Как показано |
|---|---|
| Наведение | Свечение по контуру: `--glow-1` + `--edge-strong` |
| Выделено | Заливка `--glow-2` и полоса `--text-1` слева |
| В эфире | Подложка `--live-soft` и полоса `--live` слева |

**Единственный цвет со значением — эфир.** `--live` означает ровно одно:
«это сейчас в зале», и больше нигде не встречается. Оператор следит за ним
краем глаза, поэтому в каждом стиле он подобран так, чтобы не сливаться
с акцентом: в тёплых стилях эфир малиновый, а не алый.

**Поверхности** идут от дальней к ближней: `--surface-0` фон программы,
`--surface-1` панели, `--surface-2` поля и кнопки, `--surface-3` активное.
В тёмных стилях каждая следующая светлее, в светлых — наоборот, глубже.
Границы — волосяные (`--edge`), глубину даёт разница поверхностей, а не тени.

**Единственная сплошная плашка в программе — кнопка «Показать»**, и красится
она акцентом стиля. Так главное действие невозможно перепутать с остальными.

**Шрифты зашиты в сборку**, а не подключены ссылкой: в аппаратной может
не быть интернета. Inter — интерфейс, Onest — текст слайдов, Literata и
PT Serif — засечные для Писания. Все с кириллицей, вместе ~156 КБ.
Цифры в списках выводятся моноширинно (`tabular-nums`), чтобы колонки
не дёргались при листании.

**Микрозаголовки** панелей — прописные с разрядкой `0.13em`, без заливок
и разделительных линий.

**Свои списки и палитра вместо системных.** `<select>` и `<input type="color">`
Windows рисует светлыми окнами поверх чёрного интерфейса — в тёмном зале это
бьёт по глазам. Оба заменены своими компонентами
([`Select.tsx`](src/renderer/src/components/Select.tsx),
[`ColorPicker.tsx`](src/renderer/src/components/ColorPicker.tsx)). Они
раскрываются через `position: fixed`, иначе панели с `overflow: hidden`
их обрезали бы.

**Подсветка фокуса рисуется внутрь элемента** (`box-shadow: inset`).
Обводка снаружи вылезала за край панели и обрезалась прокруткой.

**В «Управлении» сжимается только нижняя часть.** По умолчанию flex ужимает
все элементы колонки поровну, и при длинной галерее фонов строка
«Оформление: …» съезжала под вкладки настроек. Верхние ряды помечены
`flex: none`, растёт и прокручивается только `.control__body`.

## Что настраивает «Управление»

Панель правит **то, что открыто**, и подписывает это над вкладками настроек.

| Где | Что правится |
|---|---|
| «Библия» | Оформление всей вкладки |
| «Тексты», текст открыт | Только этот текст; правка сохраняется вместе с ним |
| «Тексты», ничего не открыто | Оформление вкладки — с него начинаются новые тексты |
| «Песни» | Оформление вкладки; фон — её же, если у песни не отмечен свой |
| «Песни», отмечен свой фон | Фон только этой песни; остальное — вкладки |

Так сделано не для удобства, а потому что иначе панель врала: у текста есть
своё оформление (его задаёт заготовка вроде «Темы проповеди»), и оно
перекрывало общее. Половина настроек крутилась вхолостую — кегль и выключка
на слайде не менялись.

Кнопка внизу вкладки «Текст» сбрасывает к тому уровню, что выше: у открытого
текста — к оформлению вкладки, у вкладки — к заводскому.

## Оформление у каждой вкладки своё

Писание набирают спокойным шрифтом, объявления — крупнее, песни ещё иначе.
Поэтому шрифт, кегль, цвет и фон хранятся отдельно для «Библии», «Текстов»
и «Песен»: настройка в одной вкладке не трогает другие. Шаблоны, наоборот,
общие — их для того и сохраняют, чтобы применять где угодно одним кликом.

Цвет текста выбирается полной палитрой: квадрат насыщенности, полоса оттенка,
поле для точного кода и кнопка «под фон» — она считает яркость фона (для
фотографии по её же пикселям) и ставит белый или тёмный.

**Белый текст на белом фоне** заметят в зале раньше, чем за пультом, поэтому
при выборе фона программа проверяет контраст и, если текст читаться перестал,
меняет и его цвет. Порог 4,5:1 — из правил доступности: для крупного текста
там хватает и 3:1, но это про монитор в комнате, а проектор в зале с окнами
теряет половину контраста ещё до того, как свет дойдёт до глаз. Читаемый цвет
не трогается — он выбран не случайно.

Со своими картинками и видео так же: яркость у них берётся из них самих —
кадр уменьшается до 32×18 и складывается яркость пикселей. У видео кадр
берётся не первый, а с середины: ролики часто начинаются с чёрного. Если файл
не читается или кодек незнаком, цвет не трогается вовсе.

Считается яркость **линейная**, по формуле sRGB, а не «на глаз»: экранные
значения сжаты гаммой, и серая фотография вышла бы вдвое светлее, чем она
есть, — текст на ней менялся бы зря.

**Галочку «Тень под текстом» программа не трогает вовсе.** Тень нужна, чтобы
отделить буквы от того, что под ними, и цвет у неё противоположен тексту:
под светлым текстом тёмная, под тёмным — светлая. Чёрная тень под чёрным
текстом на светлой фотографии только пачкала бы буквы, а разделить их
ни с чем не может.

Раньше на светлом фоне галочка снималась сама — и обратно на тёмном фоне
уже не включалась: текст оставался без тени там, где она нужнее всего.
Теперь снимать нечего, тень сама идёт за цветом текста. То же и в экспорте
в PowerPoint.

## Расстановка панелей

Границы между панелями подвижные — потяните за промежуток. Двигаются панели
нижнего ряда и высота между рядами; размеры запоминаются отдельно для каждой
вкладки, кнопка «сбросить вид» в заголовке «Управления» возвращает исходные.

Четыре колонки «Класс / Книга / Глава / Стих» намеренно не тянутся: ширина
у них своя и постоянная, а разделители только раздвигали бы их лишними
отступами.

Отступ между панелями задаёт сама разделительная полоска, а не `gap`
контейнера. Иначе к её ширине прибавлялись бы промежутки с обеих сторон,
и панели расходились бы на 30 пикселей вместо 10.

Панель с нулевой шириной в
[`layout.ts`](src/renderer/src/state/layout.ts) — та, что занимает остаток
и тянется при изменении размера окна; остальные держат заданную ширину.
У верхнего и нижнего ряда свои наборы ширин: один массив на оба ряда не
годится, когда в них разное число панелей.

**Границы ограничены с обеих сторон.** У каждой панели свой минимум —
у «Управления» он больше остальных, иначе «Показать» и «Скрыть» перестают
помещаться рядом. Сверху ширина ограничена так, чтобы соседям и тянущейся
панели осталось место: утащить панель за край экрана нельзя.

## Верхняя строка меню

Всё, что программа умеет, но не выносится на кнопку, собрано в одном месте.
Оператору не надо помнить, в какой вкладке спрятан импорт песен: меню всегда
на виду и всегда одно и то же.

**Файл** — новое служение, песня, текст; импорт песен, презентации, фотографий
и папки целиком;
модули Библии с сайта и импорт модуля из папки; экспорт песни; корзина;
папка с данными — её и копируют при переносе на другой компьютер; выход.

Модули с сайта стоят выше папки с диска: так их берут в девяти случаях
из десяти, а папку указывают, когда модуль уже скачан или принесён на флешке.

**«Экспорт песни…» ничего не сохраняет, а приводит туда, где выбирают.**
Он переключает на вкладку «Песни»: там видно, какая песня открыта,
и «экспорт» в её заголовке сохраняет именно её.

**Действия** — всё про эфир: показать и убрать слайд, чёрный экран, только
фон, караоке, ход служения, пульт проповедника, снимок слайда. Переключатели
помечены галочкой, и видно, включён ли чёрный экран, не глядя на зал.

**Вид** — вкладки, возврат расстановки панелей и оформления той вкладки,
которая открыта, полный экран.

**Стили** — оформление самой программы, тринадцать штук (см. ниже).

**Язык** — русский и английский.

### Корзина

Удалённое не пропадает: песня, текст или служение переезжают в корзину
своего файла. Так было с самого начала — «снести не ту песню перед служением
слишком легко», — но добраться до корзины можно было только через сам файл:
окна у неё не было, а восстановление умели одни тексты, и то без кнопки.

Теперь она видна: **«Файл» → «Корзина…»**. Три вкладки по числу библиотек —
песни, тексты, служения, — у каждой строки «вернуть» и «стереть». Первое
кладёт обратно в библиотеку и убирает из корзины, второе уносит навсегда.

**Опустошение спрашивает дважды.** «Очистить корзину» после первого нажатия
превращается в «Точно стереть всё? Нажмите ещё раз» и краснеет; уход на другую
вкладку сбрасывает подтверждение. Отдельная строка стирается одним нажатием:
она и так уже удалена, второй вопрос был бы придиркой.

Сколько помнится: песни — последние сто, тексты и служения — последние
полсотни. Дальше самое старое вытесняется само.

Общая часть — [`src/main/bin.ts`](src/main/bin.ts): три библиотеки устроены
одинаково (`{ items, trash }`), и корзина у них одна на всех, поверх готового
хранилища. У возвращённого снимается отметка `deletedAt` — вернувшееся ничем
не отличается от того, что никогда не удаляли.

**Справка** — горячие клавиши и «О программе» из двух вкладок: «Общее» —
что это за программа и что она делает; «История» — что и когда менялось.

**В «Общем» нет ни пути к папке данных, ни версий Electron и Chromium.**
Папка открывается из «Файла», а номер сборки Chromium человеку не говорит
ничего: это сведения для того, кто чинит, а не для того, кто служит.
Освободившееся место оставлено под ссылку на сайт программы — оттуда будут
скачиваться и она сама, и модули Библии на разных языках.

История лежит одним списком в `src/shared/history.ts`, обе строки — русская
и английская — рядом. Держать летопись в словаре перевода было бы неудобно:
это не подписи к кнопкам, а записи, которые дописываются пачками. Новая
запись добавляется сверху.

**«Стили» — про саму программу, а не про слайды.** Оформление слайдов
правится в «Управлении», и у каждой вкладки оно своё: общее меню сделало бы
вид, будто настройка одна на всю программу, — а это не так. Стиль окна,
наоборот, один на всё, и потому лежит в меню.

Системное меню окна отключено: своя строка нарисована внутри, а системная
перехватывала бы F11 поверх неё — и «Во весь экран» срабатывало бы дважды,
то есть никак.

**Пока что-то раскрыто, за шапку окно не тащится.** Полосы, за которые
двигают окно (строка меню и ряд вкладок), — это не оформление, а дырка
в странице: Windows считает их рамкой окна и мышь до страницы не доводит.
Меню из верхней строки свисает прямо на ряд вкладок, и его первые пункты
оказывались в этой дырке — не подсвечивались и не нажимались, будто их там
нет. Выглядело это не как поломка, а как «иногда не срабатывает».

Поэтому [`lib/dragless.ts`](src/renderer/src/lib/dragless.ts) на время
вешает на страницу класс, снимающий перетаскивание с обеих полос. Делают
это все, кто раскрывается поверх страницы: верхняя строка меню, меню
по правой кнопке (у нижнего края экрана оно разворачивается вверх и достаёт
до самого верха), свои раскрывающиеся списки и окошки «Горячие клавиши»
и «О программе». Открытые окошки считаются: закрывшееся первым не вернёт
перетаскивание, пока открыто второе.

**Вложенное меню стоит вплотную к родителю.** Зазор в три пикселя между
ними мышь успевала пересечь «наружу», и меню закрывалось прямо по дороге
к нему.

**Флагов у языков нет.** Флаг страны и язык — разные вещи, а Windows
цветных флагов не рисует вовсе: вместо них система показывает две буквы
в рамочках, и в меню это выглядело поломкой.

### Стили интерфейса

Тринадцать оформлений, тремя кучками:

| Кучка | Стили |
|---|---|
| Тёмные | Ночь, Графит, Полночь, Хвоя, Слива, Кофе |
| Светлые | День, Бумага, Туман, Небо |
| Яркие | Витраж, Закат, Неон |

По умолчанию — **Ночь**, чёрно-белая: оператор сидит в тёмном зале, и светлый
экран перед глазами слепит. Но зал залу рознь, и днём за подготовкой служения
светлый интерфейс удобнее, поэтому выбор есть. Стиль запоминается.

**Стиль — это только набор значений переменных.** Чтобы добавить новый,
достаточно дописать блок в `themes.css` и строку в
[`src/shared/themes.ts`](src/shared/themes.ts); ни один компонент трогать
не нужно. Самопроверка следит, чтобы у каждого стиля набор был полным:
недостающая переменная не остаётся пустой, а достаётся от «Ночи» — и в светлом
стиле это белый текст на белом.

**Кружок рядом с названием стиля — это он сам.** Атрибут `data-theme`
работает на любом элементе, не только на странице целиком, поэтому образец
в меню — пустой кружок с `data-theme` нужного стиля: краски он берёт оттуда же,
откуда и сам стиль, и разойтись с ним не может.

**Рамку окна красит Windows, а не страница.** Полосу с кнопками в правом
верхнем углу рисует система, и при светлом стиле там остался бы тёмный
прямоугольник. Поэтому окно после смены стиля получает три цвета —
`app:chrome`, — снятых с того, что получилось на самом деле
(`--surface-0`, `--surface-1`, `--text-2`). Они же ложатся в настройки:
следующий запуск открывает окно сразу в своём стиле, без чёрной вспышки.

**Окна вывода стиль не трогает.** В зале свои цвета — те, что заданы
оформлением слайдов; сцена и трансляция остаются чёрными.

### Значок программы

Лежит одним файлом — `resources/icon.png`, 1024×1024, со скруглёнными углами
и прозрачностью снаружи. Оттуда его берут все разом: пульт и **все три окна
вывода** (они видны в панели задач, и стандартный значок Electron выглядел бы
среди них чужой программой), знак в шапке и в «О программе»,
а `resources/icon.ico` — установщик и сам `.exe`. В `.ico` собраны все размеры от 16 до 256: мелкие Windows иначе
ужимает сама и делает это грубее.

Внутрь программы знак попадает по своей схеме — `visio://app/icon.png`:
страница живёт на `file://` и до файла напрямую не дотянется. Если файла нет,
знак просто не показывается, а программа работает как обычно.

Исходник художника лежит рядом — `resources/icon-source.webp`, без скругления.

### Язык интерфейса

Русский и английский, переключаются в меню **Язык** — на месте, без
перезапуска: подписи, подсказки, названия фонов, разделов Библии и частей
песни меняются сразу, а предпросмотр пересобирается (подпись части попадает
в сам слайд, а не рисуется поверх). Выбор запоминается.

**Содержимое не переводится, и это намеренно.** Названия служений, песни,
объявления, книги Библии — это то, что набрал или принёс оператор; менять
их вслед за интерфейсом было бы порчей данных. Книги называются так, как их
зовёт сам модуль перевода: у русского Синодального — «Бытие», у английского
будет «Genesis».

Словарь — один файл на язык (`src/shared/i18n/`). Русский в нём источник:
самопроверка сверяет ключи и следит, чтобы места для чисел («{n}») не
разъезжались, а формы числа шли по правилам языка — «1 стих», «2 стиха»,
«5 стихов» против «1 verse», «2 verses». Новый язык добавляется одним файлом.

### Снимок слайда

`Ctrl+Shift+S` сохраняет то, что сейчас в зале, картинкой 1920×1080 — в общий
чат, в ленту церкви, в отчёт.

Снимается не окно зала, а та же страница, нарисованная закадрово. Окно зала
не годится: на одном мониторе оно открывается маленьким окошком рядом
с пультом, и снимок вышел бы такого же размера. Обычное скрытое окно тоже
не годится — Windows ужимает его до размеров экрана, и кадр перестаёт быть
16:9. Закадровое окно ни во что не упирается, и размер задаётся ещё раз уже
готовому окну: при создании его правит и рамка, и масштаб экрана.

### Горячие клавиши

| Клавиша | Что делает |
| --- | --- |
| `F5` | Показать слайд той вкладки, которая открыта |
| `Esc` | Убрать слайд |
| `Пробел` | Дальше: по частям песни, по слайдам, по служению |
| `F12` · `B` | Чёрный экран |
| `Ctrl+F5` · `T` | Только фон, без текста |
| `K` | Караоке; `Enter` — отметить строку спетой |
| `Ctrl+Z` | Отменить последнее действие |
| `Ctrl+Shift+Z` · `Ctrl+Y` | Вернуть отменённое |
| `Page Down` `Page Up` `.` | Пульт проповедника: шаг внутри пункта и чёрный экран |
| `→` `←` | Шаг по стихам, частям песни, слайдам |
| `↓` `↑` | Шаг по слайдам длинного места |
| `Ctrl+1…4` | Главная, Библия, Тексты, Песни |
| `F11` | Во весь экран |
| `Ctrl+Shift+S` | Снимок слайда картинкой |
| `F1` | Подсказка по клавишам |

F-клавиши и сочетания с Ctrl работают и в полях ввода: текста они не портят,
а показать слайд посреди правки объявления бывает нужно. Остальные — нет:
оператор набирает текст спокойно.

Отмена — среди первых: она работает и в полях ввода. Своя отмена браузера
там не годится, она знает только про это поле, а вернуть надо и удалённую
песню, и уроненный мимо места пункт плана. Набранное при этом отменяется
словами, а не буквами, — так что в поле она ведёт себя привычно.

## Отмена

`Ctrl+Z` отменяет последнее действие — по всей программе, а не в одном поле
ввода. Снесли не ту песню, стёрли куплет, уронили пункт служения мимо места,
очистили план проповеди — всё возвращается одним нажатием. `Ctrl+Shift+Z`
возвращает отменённое обратно.

Спрашивать «точно?» перед каждым действием нельзя: на служении лишний вопрос
дороже ошибки — руки жмут «да» раньше, чем глаза читают. Поэтому не
подтверждение, а отмена.

**Внизу окна на пару секунд появляется подпись, что именно вернулось** —
«Отменено: удаление пункта „Благодарности и нужды“». Без неё отмена была бы
прыжком в темноте: она почти всегда меняет то, чего сейчас не видно на
экране, — песню в другой вкладке, пункт ниже видимой части плана.

**Набранное слово отменяется целиком, а не по букве.** Соседние правки одного
поля, случившиеся ближе чем через девятьсот миллисекунд, считаются одним
действием: девятьсот — это пауза между словами, а не между буквами.

**Шаги не хранят состояние целиком** — только замыкания на своё «до»
и «после». Снимок всей библиотеки на каждое нажатие клавиши был бы и тяжёл,
и неверен: пока шаг лежит в стопке, соседние данные могли измениться,
и возвращать их скопом нельзя. Помнится восемьдесят шагов — это всё служение,
и не больше.

## Вкладка «Главная»

Пульт служения. Устроен как остальные вкладки: сверху дерево служений и план,
снизу предпросмотр и управление. Раньше здесь была своя раскладка в три
колонки с отдельным «Окном слайда» — она ничем не походила на другие вкладки,
и оператор каждый раз перестраивался.

**Служения лежат в папках, как файлы в проводнике.** Папки вложенные —
«2026 → Август → 24 августа», — перетаскиваются мышью, переименовываются
по двойному щелчку. Служение перетаскивается в папку так же и так же
переименовывается прямо в дереве: раньше имя правилось только в поле справа,
а до него надо было сначала открыть нужное служение. Во время служения
переименование выключено, как и остальная правка плана.

Удаление папки уносит и вложенные папки, но **не служения**: они поднимаются
на уровень выше. Снести годовой архив одним промахом нельзя.

**Папка хранит ссылки, а не копии.** Поправив песню один раз, оператор меняет
её во всех папках, где она стоит. Рядом со ссылкой лежит подпись — чтобы папка
оставалась читаемой, даже если элемент из библиотеки удалили. Если песня
используется в нескольких папках, рядом с ней стоит число.

**Заготовок хода служения нет намеренно.** У каждой церкви он свой, и чужой
порядок пришлось бы сначала разбирать. Вместо них — «копия»: прошлое
воскресенье копируется целиком со всеми пунктами, и остаётся заменить песни
и проповедь.

**Пункт добавляется из своей вкладки.** В «Песнях» и «Текстах» правая кнопка →
«Добавить в служение», в «Библии» — «Добавить в план». Раньше приходилось
идти в «Главную» и искать нужное заново в выпадающем списке.

**Пункты** бывают пяти видов: песня, текст, место Писания, показ (презентация
или фотографии) и заметка. Заметка в зал не выводится и при «Далее» пропускается — это
напоминание оператору.

**Чужие презентации.** Проповедь или благословения приносят готовым файлом,
и переверстать их в наши слайды нельзя — там своё оформление, схемы,
фотографии. Поэтому `.pptx` и `.pdf` раскладываются на слайды-картинки,
и презентация становится обычным пунктом плана: листается «Далее», видна
в предпросмотре, слушается тех же клавиш. Под планом появляется лента
слайдов — по ней видно, что дальше, и можно прыгнуть на нужный, когда
проповедник вернулся к предыдущей мысли.

`.pptx` рисует сам PowerPoint: своего разбора хватило бы на текст, но не на
вид — шаблоны, схемы, шрифты умеет только он. `.pdf` рисует встроенный
просмотрщик Chromium, он и так есть в программе.

**Фотографии.** Снимки приносят так же, как презентации: «вот объявления
на воскресенье», «вот фотографии с крещения». Раскладывать в них нечего —
снимок уже картинка, — поэтому они просто ложатся в показ по порядку
и листаются той же кнопкой «Далее», с той же лентой под планом.

Папка — это и есть показ. Двадцать снимков из одной папки встают в план
одним пунктом, а не двадцатью строками подряд; пункт зовётся по папке.
Одинокий снимок зовётся по имени файла: «Рабочий стол» в плане служения
не говорит ни о чём.

Порядок внутри папки числовой: по буквам «Фото 10» оказывается перед
«Фото 2», и объявления шли бы задом наперёд.

Большие снимки ужимаются до кадра проектора. Фотография с телефона —
это двенадцать мегапикселей и пять мегабайт, а в зал идёт 1920×1080:
без этого папка с сорока снимками весила бы триста мегабайт, и лента
под планом открывалась бы по несколько секунд. Видно при этом ровно то же
самое. Не трогаем то, что и так меньше кадра, `.gif` (он бывает
с движением) и то, что Electron не смог прочитать сам, — такое копируется
как есть. Прозрачность сохраняется: у `.png` и `.webp` ужатый снимок
остаётся PNG, иначе логотип с прозрачным полем залился бы белым.

**Папку раскладывают по смыслу.** В одной папке приносят и проповедь,
и снимки: каждая презентация становится своим пунктом — их показывают
в разных местах служения, — а все фотографии собираются в один показ.
Своя копия обязательна и здесь: файлы приносят на флешке, а служение
должно открыться и через год.

В плане и на пульте такой пункт подписан «Фото», а не «Презентация»:
внутри они устроены одинаково, но гадать, что там на самом деле, оператору
незачем.

**Показ можно сделать песней.** Песни часто приносят той же презентацией:
куплеты по слайдам, фон общины, всё готово — только поправить нельзя ни буквы,
и караоке по картинке не идёт. Правая кнопка на пункте → **«Сделать песней»**:
программа берёт текст со слайдов исходного файла, кладёт песню в библиотеку,
ставит её в плане **на место презентации** и открывает в «Песнях» — оператор
видит, что получилось.

Презентация из плана при этом уходит. Держать её рядом с песней, сделанной
из неё же, оказалось хуже, чем казалось: в плане стоят два пункта с одним
названием, и посреди служения в зал уходит не тот. Ошибиться здесь легче
всего именно тогда, когда ошибиться нельзя.

Убирается пункт плана, а не сам показ: картинки остаются в библиотеке показов,
и вернуть презентацию в план можно в любую минуту. А если разбор не удался,
план вообще не меняется — программа говорит, почему не вышло, и показ стоит
где стоял.

**Каждый слайд становится своей частью.** Границы куплетов в презентации уже
расставлены руками, и разбирать их заново по пустым строкам значило бы гадать
там, где гадать не нужно: куплет из двух четверостиший разъехался бы надвое.
Слайд из одного заголовка — «Куплет 2», «Припев:» — это подпись к следующему,
а не часть: такие слайды в песенных презентациях делают нарочно.

**Фон бывает и не картинкой.** Сборники песен верстают готовыми темами
PowerPoint, и внутри такого файла картинок может не быть вовсе: кремовый фон
записан ссылкой на заливку в теме. Пока искали только `ppt/media`, песня
из такой презентации приходила на чёрной подложке — фон терялся целиком.

Достаётся он в три перескока. Слайд говорит «фон как в разметке», разметка —
«как в образце», образец — `<p:bgRef idx="1003">` с цветом `bg2`. Дальше
`idx` — это номер заливки в списке темы, а `bg2` — имя из карты цветов,
которое ведёт в палитру темы за настоящим кодом. И только там оказывается,
что кремовый — это #E3EACF.

Заливка переводится в CSS: ровный цвет так и остаётся цветом, переливка —
переливкой, с теми же поправками, что накладывает тема (осветление,
затемнение, яркость, насыщенность). Круговая заливка сохраняет и место
светлого пятна: у многих тем оно стоит не по центру.

Сверено с самим PowerPoint: слайд экспортирован в картинку и промерен
по точкам. В середине у темы «Лёгкий дым» ровно белый — столько же выдаёт
и разбор; по краям #dfe8c4 против наших #dce5c2, разница в один-два уровня
из двухсот пятидесяти шести.

Чего этот путь не умеет — рисованных украшений. Травинки по левому краю
той же темы нарисованы фигурами в образце, и в CSS их не пересказать:
фон выйдет кремовым, но без них. Заливку это отдаёт целиком, а её и видно
на слайде больше всего.

**Заливки тоже ложатся в галерею.** Картинка кладётся в папку файлом,
а заливка — это несколько строк CSS, файла из неё не сделать. Поэтому свои
заливки живут списком рядом с картинками, а в «Управление → Фон» стоят
вперемешку с ними: человеку всё равно, чем его фон нарисован. Одинаковые
второй раз не заводятся — сравниваются по самому CSS.

В галерею уходит не один фон, а все, что нашлись в файле: слайды одного
сборника бывают на разных заливках, и каждая из них — готовый фон, который
общине ещё пригодится. Песне достаётся первый.

**Фон-картинка** лежит внутри `.pptx`, в `ppt/media`,
вперемешку с логотипом общины и значками списков, и узнаётся не по размеру,
а по тому, что на него ссылается образец слайдов: логотип в углу повторяется
на каждом слайде не реже фона. Картинка, на которую не ссылается никто, — это
обрезок, оставшийся в файле, и фоном не считается. Дальше фон живёт при песне
и меняется галочкой «Свой фон у этой песни» в «Управлении».

**Чужой PowerPoint не закрываем.** Текст из старого `.ppt` достаёт сам
PowerPoint, и запускается он одним на всю систему: если оператор в это время
работает в PowerPoint, программа подключается к его окну. Закрыть такое
окно после разбора значит закрыть и то, что человек не сохранил. Поэтому
перед разбором считается, сколько презентаций уже открыто: есть чужие —
PowerPoint остаётся работать, свой невидимый закрывается как прежде.

Старый `.ppt` разбирается тоже. Формат двоичный и закрытый, поэтому текст
из него достаёт сам PowerPoint через COM — как и при раскладке показа
на слайды. Он же пересохраняет презентацию в нынешний формат, и фон берётся
уже оттуда: из `.ppt` его не вытащить. Нет PowerPoint — программа говорит
об этом словами, а не молчит.

Каждая страница PDF открывается заново, через пустую страницу посередине.
Просто поменять «#page=N» в адресе мало: браузер считает это переходом внутри
той же страницы, ничего не перезагружает, и просмотрщик остаётся на первом
листе — в презентации выходили тридцать четыре копии титульной страницы.
Клавиши и колесо мыши до него тоже не доходят: он живёт отдельным модулем,
а окно у нас невидимое.

Сколько ждать отрисовки, заранее неизвестно: лист с одной строкой готов
сразу, лист с фотографиями — через секунду. Поэтому программа ждёт, пока
кадр перестанет меняться, а не отсчитывает наугад. Если после этого все
страницы всё равно вышли одинаковыми, импорт обрывается с внятной причиной —
молча положить тридцать копий одного листа хуже.

Лист вырезается из снимка по цвету: просмотрщик кладёт его на ровное серое
поле. Идём от середины кадра наружу — с краю внутрь нельзя, границей
окажется не наш лист, а полоса прокрутки или край следующей страницы.
Краем считается сплошная полоса цвета поля, а не одиночная точка: на тёмном
слайде хватало одного случайного пикселя, чтобы обрезка встала посреди буквы
и слайд превращался в увеличенный обрывок. И меряем не одну строку, а пять,
беря самый широкий разброс, — строка могла попасть в промежуток между
абзацами. Если лист сам почти в цвет поля, границ не видно вовсе: тогда
берётся весь снимок, с узкими полями по краям. Картинки хранятся рядом
с библиотекой, а не ссылкой на файл: исходник принесли на флешке, а служение
должно открыться и через год.

**Кнопки «+ Песня», «+ Текст», «+ Писание» не добавляют сами**, а уводят
в нужную вкладку — оттуда пункт кладут в план правой кнопкой. Так он попадает
в служение обдуманно, а не первым, что подвернулось в выпадающем списке.

**Один клик выбирает, два открывают.** Клик по пункту говорит программе, что
это и есть «то, что сейчас на очереди»: пункт подсвечивается серым, правая
панель показывает именно его, под планом появляется его лента слайдов,
а «Показать» и стрелки шага работают с ним. Раньше выбранного пункта не было
вовсе — и «Начать служение» начинало со следующего за нажатым: оператор жал
на первую песню, а в зал уходила вторая.

Открывает пункт двойной клик — он уводит в его вкладку на правку. Одиночный
этого не делает намеренно: мимоходом задетый пункт уносил бы оператора
со служения. Исключение одно — показ: он открывается и одним кликом, потому
что править в нём нечего, а лента слайдов под планом нужна сразу.

**Красное — это эфир, серое — выбор.** Красным помечен только тот пункт,
который прямо сейчас на экране в зале; убрали слайд — метка погасла. Раньше
красным оставался последний, по которому щёлкнули, и снять её было нечем:
к середине служения в плане горели три «текущих» пункта разом, и по цвету
нельзя было понять ничего.

**Порядок правится мышью.** Пункт перетаскивается на своё место; черта
показывает, куда он встанет — выше строки или ниже. «Выше» и «Ниже» в правой
кнопке остались: они удобнее, когда сдвиг на одну строку. А песню из конца
в начало ими пришлось бы двигать шесть раз. Во время служения перетаскивание
выключено — задеть план мышью, пока идёт пение, слишком легко.

**Файл можно бросить прямо в план.** Оператор приходит с флешкой: проповедь
в `.pptx` и папка с песнями. Всё это перетаскивается из проводника прямо
на план, целой пачкой и без окна выбора файлов. `.pptx`, `.ppt` и `.pdf`
раскладываются на слайды и показываются как есть; остальное разбирается как
песня, ложится в библиотеку и сразу встаёт в порядок служения. Папку можно
бросить целиком — она разворачивается сама, вместе с вложенными.

Что не открылось, программа говорит словами: «на этом компьютере не
установлен PowerPoint» подсказывает, что делать дальше, а молчание — нет.

**Пульт** — правая панель «Главной». На служении оператор смотрит только
туда, и смотрит быстро, поэтому там ровно то, что нужно на ходу, и в том
порядке, в каком к этому тянутся руки: «Далее»; сколько идёт служение
и какой пункт из скольких; что сейчас на экране и на каком месте внутри
пункта («часть 2 из 5», «слайд 3 из 12») со стрелками шага; что будет
следующим — чтобы объявить, не листая план; чёрный экран и «только фон».
Настроек оформления там нет намеренно: их правят до служения, а на служении
лишняя кнопка — это ошибка в зале.

Стрелки шагают внутри любого пункта: по частям песни, по слайдам текста,
по страницам презентации, по слайдам места Писания. Так же работают стрелки
на клавиатуре, пока открыта «Главная»: раньше они уходили в «Библию»,
и посреди чужой презентации в зал уезжали стихи из первой главы Бытия.

Шаг сам по себе зал не зажигает — как и у песен: при погашенном экране
стрелка только двигает место, а не выбрасывает в зал случайный слайд.
Показывает `F5`, «Показать» или двойной щелчок по ленте.

**Показ кончился — «Далее» гасит экран, а не выводит следующий пункт.**
Раньше лишнее нажатие на последнем слайде проповеди сразу выбрасывало в зал
заглавие следующей песни. Проповедь идёт, оператор дожал кнопку на один раз
больше — и поверх последнего слайда встало чужое. Отыграть назад можно,
но в зале уже увидели.

Теперь лишнее нажатие всего лишь убирает слайд, как `Esc`: экран пуст, это
видно и оператору, и залу, и ничего чужого туда не ушло. Следующее нажатие
идёт дальше по служению, порядок не ломается. Песен и мест Писания это
не касается: там конец части — дело обычное, а презентация идёт полчаса,
и лишнее нажатие в ней куда вероятнее.

**Лента слайдов листается колесом мыши.** Лента лежит поперёк, а колесо
крутится вдоль — само собой это не работает: вместо ленты уезжала панель
под ней, и оператору оставался ползунок в три пикселя высотой. Теперь колесо
над лентой двигает её вбок и панель не трогает. Лента и сама едет за слайдом:
листают её не только мышью, но и пультом проповедника.

**Выбранный слайд обведён рамкой, которую видно всегда.** Рамка рисуется
поверх картинки, а не под ней: раньше это была внутренняя тень, снимок слайда
ложился сверху и съедал её — обводка обрывалась посреди слайда. И цвет брался
из темы: на светлой теме он тёмный, а слайды почти всегда чёрные, и рамку
было не разглядеть вовсе. Теперь две краски разом — светлая линия с тёмной
подложкой, — и она читается на любом слайде в любой из тринадцати тем.

**Режим служения.** «Начать служение» — и дальше работает одна кнопка «Далее»:
она доводит до конца текущий пункт и переходит к следующему, сама переключая
вкладку. Что значит «до конца», знает та вкладка, которая пункт показывает,
поэтому песня проходится по частям, а место Писания — по слайдам.

Пробел во время служения ведёт по папке из любой вкладки. Редактирование
папки при этом заблокировано.

**Правка в два клика.** Двойной клик по пункту открывает его в нужной
вкладке, а в шапке появляется «← Назад к служению» — она возвращает на то же
место.

## Пульт проповедника

Беспроводной презентер — это для компьютера обычная клавиатура. Своего
протокола у него нет: он шлёт те же клавиши, которые PowerPoint слушает уже
двадцать лет. Значит, и «поддержка пульта» — это согласие слушать те же
клавиши, и ставить для неё ничего не нужно: воткнули приёмник в USB — работает.

| Кнопка | Что делает |
|---|---|
| `Page Down`, `→` | Вперёд по слайдам того пункта, что сейчас в зале |
| `Page Up`, `←` | Назад по тем же слайдам |
| `F5` | Показать слайд |
| `Esc` | Убрать слайд |
| `.` | Чёрный экран |

**Шагаем внутри пункта, а не по служению.** Проповедник листает свои слайды,
а не ведёт порядок собрания — тот остаётся у оператора. Промахнуться кнопкой
и уехать на следующую песню посреди проповеди нельзя.

**Пульт листает то, что на экране, а не то, что открыто у оператора.**
Это разные вещи, и раньше пульт слушался вкладки: оператор уходил в «Библию»
готовить следующее чтение — и кнопка пульта уводила проектор туда же, посреди
песни. Теперь тот, кто вывел слайд в зал, оставляет программе способ сделать
шаг, и пульт спрашивает только его. Песня, текст, место Писания, презентация —
всё листается одинаково, а вкладка при этом может быть любая.

Идёт служение — шагает пункт плана, тот самый, что в зале: у песни за
последним куплетом стоит не пустота, а следующий пункт, и знает об этом
только план.

На экране пусто — стрелки возвращаются к открытой вкладке: тогда оператор
готовит показ, и двигать надо подготовку.

**Пульт работает и когда программа не в фокусе.** Оператор сворачивает окно
и ищет файл в проводнике, а проповедник в это время листает свои слайды —
и до окна программы нажатие не доходит вовсе. Поэтому `Page Up` и `Page Down`
перехватываются у самой Windows.

Перехват включается только на время показа: пока в зале что-то есть. Вне
показа эти клавиши должны листать чужие окна, как и положено, — программа
их отдаёт обратно, как только экран погас. Выключается галочкой «Работает,
когда программа не в фокусе» в том же окошке «Действия → Пульт проповедника».

Точка гасит экран потому, что так гасит показ PowerPoint и так подписана
кнопка на самих пультах. Считается и точка цифрового блока: пульты шлют
то одну, то другую.

**Нажатие ловится и в окне зала.** Проповедник стоит у кафедры, окно оператора
на своём мониторе, а нажатие уходит в то окно, которое сейчас в фокусе, —
и это чаще всего зал. Окно вывода ничего не решает само: оно пересылает
клавишу пульту, и дальше всё идёт обычным путём.

**«Действия → Пульт проповедника»** отвечает на два вопроса, и второй важнее
первого.

Первый — что вообще подключено. Windows знает про свои устройства и охотно
рассказывает, но половина пультов представляется ей как «USB-устройство
ввода», неотличимо от мыши. Поэтому список — подсказка, а не ответ: похожее
на пульт стоит наверху, остальное свёрнуто в строку «остальные устройства
ввода: 3».

Второй — работает ли он. Единственный честный ответ здесь даёт сама кнопка
на пульте: нажали — окошко это увидело и назвало клавишу. Ни один список
устройств такого не докажет, а перед служением проверить нужно именно это.

Галочка «Слушать пульт» стоит по умолчанию: эти клавиши в программе больше
ничем не заняты, и выключать то, чего человек не включал, значит заставить
его сперва найти настройку. Снять её можно — если пульт мешает.

## Папки в библиотеках

**Песни и тексты лежат в таких же папках**, как служения: «Прославление»,
«Причастие», «Детские». Дерево одно и то же, различается только область —
служения, песни или тексты. Папки вложенные, всё перетаскивается,
переименование по двойному щелчку — и папки, и самой песни или текста,
не открывая их.

**Дерево видно и в пустой библиотеке.** Раньше подсказка «пока пусто»
занимала его место целиком, и заведённая папка оказывалась нигде — её не
видел даже тот, кто её только что создал. А папки как раз и заводят заранее,
до того как принесут песни.

Пока в строке поиска что-то набрано, дерево уступает место плоскому списку:
искать надо по всей библиотеке, а не в той папке, которую открыли. Строка
пустеет — дерево возвращается.

**Песни перетаскиваются из проводника прямо в библиотеку.** Файл, несколько
файлов или целая папка со сборником — папка разворачивается сама, вместе
с вложенными. Если бросить на папку в дереве, песни лягут в неё, а не
в корень, откуда их пришлось бы растаскивать по одной. Формат определяется
по содержимому: у OpenSong расширения нет вовсе, поэтому файл без расширения
тоже читается, а не пропускается молча.

## Вкладка «Песни»

**Вид части меняется в один щелчок.** Чужие файлы часто приходят без
разметки, и песня ложится десятью куплетами подряд, хотя половина из них
припев. Кнопка «сменить» в заголовке части (и правая кнопка по самой части)
предлагает все виды: куплет, предприпев, припев, бридж, повтор, концовка.

Куплеты после смены перенумеровываются подряд: если третий из пяти стал
припевом, оставшиеся читаются «1, 2, 3, 4», а не «1, 2, 4, 5» — иначе
порядок пения «1-П-4» ставит регента в тупик. Текст части при этом
не трогается.

Слева библиотека с поиском по названию, автору, номеру и по любой строке
текста. Справа песня: название, автор, номер в сборнике, тональность, темп,
номер лицензии — и части.

**Текст раскладывается по частям сам.** Вставьте песню целиком: пустая строка
отделяет части, а строка «Припев:», «Куплет 2», «Бридж» или просто «2.»
задаёт вид следующей. Без заголовка часть считается очередным куплетом.
Разбор намеренно предсказуемый, а не умный: оператор быстрее поправит одну
строку в редакторе, чем будет разбираться, почему программа сочла куплет
припевом.

**Припев находится по повторам.** Песню из презентации приносят без единой
подписи: все слайды ложатся куплетами подряд, хотя половина из них — один
и тот же припев. Но повтор виден и без подписи: если один и тот же текст
встретился на нескольких слайдах, это припев, и назвать его так программа
может сама.

Ничего при этом не удаляется и не склеивается. Слайды остаются все, на своих
местах, в том же порядке — меняется только подпись части. Сравнение прощает
разницу в наборе: «Свят, свят, свят Господь!» и «свят свят свят господь» —
один и тот же припев, потому что регистр, запятые и лишние пробелы
в сравнении не участвуют.

Гадать программа не берётся. Подписи в песне уже есть — повторы не трогаем
вовсе: раз человек разметил, ему виднее. Повторяется вся песня целиком —
тоже не трогаем: это не припев, а один и тот же текст. Совпало что-то
короче восьми букв — не трогаем: на таком совпадении можно ошибиться.
Куплеты после этого перенумеровываются подряд, как и при ручной смене вида.

**Порядок пения** показывается строкой вроде `1-П-2-П-Б-П` и собирается
по умолчанию так, как поют чаще всего: припев возвращается после каждого
куплета, предприпева и бриджа. Любую часть можно добавить в порядок ещё раз
или убрать.

**Большие кнопки частей** под предпросмотром — чтобы вывести припев одним
нажатием, даже если его поют три раза подряд.

**Аккорды** хранятся рядом с текстом части и в зал не попадают никогда —
проверено отдельным тестом.

**Караоке** включается кнопкой или клавишей `K`. Спетое остаётся в полную
силу, неспетое приглушается; цвет при этом тот же самый, поэтому закраска
читается и на тёмной заливке, и на светлой фотографии.

**Цвет закраски программа подбирает под фон.** На чёрной заливке светится
любой из восьми оттенков, а на фотографии половина из них пропадает — и
понимают это уже в зале. Поэтому есть кнопка **«сам»**: программа смотрит
на фон и берёт тот цвет, который на нём читается.

Смотрит она не на весь кадр, а на ту его часть, где лежит текст, —
и не на среднюю яркость, а на крайние участки. Средняя обманывает: на снимке
с тёмной землёй и светлым небом она выходит серединной, и по ней годным
кажется любой цвет, хотя строка сольётся половинами — одна с небом, другая
с землёй. Крайние участки берутся не самым тёмным и самым светлым пикселем,
а десятой частью с каждого края: одна чёрная точка на снимке не должна
решать за весь фон.

Цвет выбирается тем же окошком, что и цвет текста: квадрат оттенков, ползунок,
поле кода и кнопка «под фон», которая включает подбор обратно. Под ним набор —
два ряда по восемь: светлые для тёмного фона и тёмные для светлого.
Берётся тот цвет, у кого контраст с худшим участком фона больше. Белый и почти
чёрный стоят в своих рядах последними: при равном контрасте побеждает цветной
оттенок, потому что цветная закраска читается как караоке, а белая — как
обычный текст.

**Цвет считается для каждой строки отдельно.** Один на весь слайд не спасает
там, где вверху небо, а внизу земля: половина строк всё равно сливается.
Поэтому безопасная зона делится на полосы — по одной на строку, — и каждая
меряется сама. Сперва ищется один цвет на весь текст, и строка меняет его
только тогда, когда он на ней не проходит порог: на ровном фоне радуги
не выйдет, цвет у всех строк будет один.

Заодно цвет не должен совпадать с цветом неспетого текста: закраска, слитая
с ним, не покажет ничего. Проверяется это отдельно от читаемости — иначе
на чёрном фоне белым закрашивалось бы белое.

Порог читаемости — 4,5:1, из правил доступности. Бывает фон, на котором его
не берёт никто: наполовину чёрная, наполовину белая фотография. Тогда берётся
самый контрастный из возможных — лучше так, чем оставить на экране то, чего
не видно.

Выбрали цвет руками — подбор выключается: раз человек выбрал, программа
не спорит. Обратно включается той же кнопкой «сам». Подбор идёт при каждой
смене фона, а не слайда: соседние куплеты лежат на одной картинке, и мерить
её заново на каждый — впустую.

**Слово закрашивается по букве, а не наливается цветом.** Прежде слово,
которое поют прямо сейчас, целиком заливалось краской — и в зале это читалось
не как караоке, а как ошибка вывода: строка вдруг меняла цвет посреди пения.
Теперь закраска бежит по буквам, слева направо, и глазу видно направление,
а не вспышку. Шагов у неё ровно столько, сколько букв в слове (`steps(n)`
в `.kar--now`), поэтому короткое слово не тянется дольше длинного.

Вести подсветку можно тремя способами.

**Руками.** Каждое нажатие `Enter` отмечает строку спетой. Под `Enter`
удобно вешать ножную педаль.

**По темпу.** Подсветка едет сама, считая строку примерно за четыре доли;
работает, если у песни задан темп.

**По голосу.** Программа слушает зал через микрофон, узнаёт слова этой самой
песни и ведёт закраску за пением.
Об этом — [отдельный раздел](#караоке-по-голосу).

Любое действие оператора перехватывает управление сразу, без вопросов
и подтверждений: переключили слайд руками — подсветка идёт оттуда.

**Свой фон у песни.** Песня из чужой презентации приносит с собой её фон —
и та, что разобрана из показа в плане, и та, что просто принесена файлом
в «Песни»: в зале она должна выглядеть так же, как выглядела бы
презентация. Живёт этот фон в «Управлении → Фон», под галочкой
**«Свой фон у этой песни»**. Галочка снята — песня возвращается к общему
фону вкладки; поставлена — фон выбирается ей одной, из той же галереи,
что и всем остальным. Так фон из презентации можно и оставить, и заменить
на свой, и убрать вовсе, не трогая при этом остальные песни.

**Фон ложится в галерею, а не только в песню.** Картинка, пришедшая
с презентацией, попадает в «свои фоны» в «Управлении» и видна там сразу —
её можно поставить любой другой песне, тексту или месту Писания. Одинаковый
фон второй раз не копируется: в сборнике одна и та же заливка стоит на всех
тридцати презентациях, и галерея состояла бы из тридцати одинаковых плиток.
Отчёт об импорте говорит об этом словами: сколько фонов легло и сколько таких
уже было.

**Номер задаёт место в библиотеке.** Пронумерованные песни стоят по номеру,
остальные — по алфавиту за ними: сборник ищут номером, и «12» должна стоять
после «11», а не между «Аллилуйя» и «Благодарю».

Номер берётся из имени файла: «01 Свят Господь» ложится первой, а название
остаётся чистым — «Свят Господь». Номером считается либо число со знаком
после него («12.», «7)», «003 -»), либо запись с нулём впереди («01»):
её ставят нарочно, чтобы файлы легли по порядку. «10 заповедей» и «Псалом 22»
остаются названиями целиком.

Поставили песне номер два — она встаёт второй, а бывшая вторая съезжает
на третью; номера пересчитываются подряд, одинаковых не остаётся. То же
делает и мышь: песню в библиотеке можно перетащить на место другой, и номер
поменяется сам. Считается это по папке, в которой песня лежит: в одной
сборник, в другой детские, и сквозная нумерация перемешала бы их.

**Счётчик исполнений** растёт на один за каждый выход песни в зал, а не за
каждый слайд, — для отчёта по лицензии.

**Своё «Управление».** У песен оно отличается от остальных вкладок: шаг
по слайдам и блок караоке. Настройки вида общие — они вынесены в `LookTabs`
и одинаковы везде.

Пояснений в «Управлении» нет намеренно: это панель, за которой работают
во время служения, а не читают. Всё, что нужно сказать, сказано подсказкой
при наведении.

**Импорт.** Формат определяется по содержимому, а не по расширению —
у OpenSong его нет вовсе:

| Формат | Что берётся |
|---|---|
| Текст (в том числе CP1251) | Текст, разложенный по частям |
| RTF | Текст; кодировка берётся из таблицы шрифтов |
| OpenSong | Название, автор, тональность, номер, текст |
| OpenLyrics (выгрузка OpenLP) | Название, автор, номер лицензии, части по именам куплетов |
| PowerPoint `.pptx` | Текст со слайдов и фон презентации; каждый слайд — часть |
| PowerPoint `.ppt` до 2007 | То же: текст достаёт сам PowerPoint, фон — из его же копии в `.pptx` |
| PDF | Название, автор, части по отступам и заголовкам |
| ProPresenter 4–6 `.pro6` | Название, автор, номер, части по названиям групп |
| ProPresenter 7 `.pro` | Части по названиям групп, если их удалось узнать |

**PDF читается без сторонних библиотек.** В PDF нет ни строк, ни абзацев —
есть буквы, расставленные по листу, поэтому строки собираются обратно
по высоте, пробелы — по промежуткам шире половины пробела в этом шрифте,
а границы куплетов — по отступам между строками и по началу новой страницы.
Русские буквы достаются из таблицы `/ToUnicode`, которую кладёт почти любой
Word или LibreOffice; для старых шрифтов есть имена начертаний (`afii10017`,
`uni0410`) и однобайтовые кодировки. Строка из одних аккордов не поётся —
в текст слайда она не попадает.

**ProPresenter — это два разных формата под одним именем.** Шестая версия
пишет XML, где текст слайда лежит base64-строкой RTF; седьмая — protobuf,
схемы к которому нет. Для седьмой сделано честное угадывание: сам RTF
внутри файла узнаётся однозначно, а подписи частей берутся только те,
что похожи на подписи («Verse 1», «Припев»), — выдумывать названия
из случайных строк файла хуже, чем оставить их пустыми.

**Титульный слайд отделяется от куплетов.** Почти в каждой чужой
презентации первым слайдом стоит название песни. Принять его за куплет —
значит сбить всё: название станет первым куплетом, настоящий первый —
вторым, и порядок пения окажется не тем, что поют. Отличить название
от куплета можно по тому, как оно написано: короткая строка в несколько
слов, не обрывающаяся запятой. Строка песни, наоборот, почти всегда
длинная и продолжается дальше — потому и кончается запятой. Если первая
строка совпала с именем файла, сомнений нет вовсе.

**Что не вышло — говорится вслух.** «В PDF нет текста, похоже, это скан»
подсказывает, что делать дальше; молчание — нет. Итог импорта показывается
в списке песен: сколько взяли, из каких форматов и какие файлы пропущены.

**Экспорт.** Библиотека песен — это годы труда, и человек должен быть
уверен, что она не заперта в этой программе. Поэтому форматов несколько,
и каждый нужен для своего:

| Формат | Зачем |
|---|---|
| Текст `.txt` | Прочитать, отправить, вставить в письмо |
| PowerPoint `.pptx` | Отдать туда, где нет VisioLogos: готовые слайды |
| PDF | Напечатать песенник; печатает сам Electron |
| OpenSong `.xml` | Отдать в OpenSong |
| OpenLyrics `.xml` | Отдать в OpenLP |

Формат спрашивается **до** окна сохранения, списком у кнопки «экспорт»:
окно сохранения не сообщает, какой тип файла в нём выбрали, а OpenSong
и OpenLyrics оба лежат в `.xml` — угадать по расширению нельзя.

Кнопка одна — **«экспорт»** в заголовке открытой песни, и сохраняет она
ровно эту песню. Выгрузки всей библиотеки разом нет: пункт меню, который
это делал, отдавал не то, чего от него ждали, — человек просил песню,
а получал всё сразу и в незнакомом формате. Библиотека целиком переносится
папкой с данными, для этого не нужен ни особый формат, ни кнопка.

**PowerPoint пишется вручную.** `.pptx` — это zip с кучей XML, и почти всё
в нём обязательное: образец слайдов, разметка, тема. Недостающую часть
PowerPoint не додумывает, а объявляет файл испорченным, поэтому все части
выписаны целиком, пусть и в простейшем виде.

Слайды делаются такими, какими их выводят в зал, — с тем же оформлением,
что стоит во вкладке «Песни»:

* **Фон рисуется картинкой.** Фоны в программе — это CSS: многослойные
  заливки с виньеткой, лучами и сиянием. Пересказать такое средствами
  PowerPoint нельзя, да и незачем: скрытое окно рисует фон ровно так, как
  его увидит зал, и снимок вкладывается в презентацию. Тем же путём
  попадают и картинки пользователя. Ровные заливки сохраняются в PNG,
  фотографии — в JPEG: PNG раздувает их в разы, и презентация с десятком
  песен перестала бы уходить почтой.
* **Кегль подбирается заранее.** PowerPoint умеет ужимать текст сам, но
  только когда его правят руками: при открытии файла длинный куплет уехал бы
  за край. Поэтому кегль подбирается тем же способом, что и в программе —
  текст ставится в коробку нужного размера и уменьшается, пока не влезет.
  Меряется тем шрифтом, который окажется в презентации: на чужом компьютере
  вшитых в программу шрифтов нет, и в перечень гарнитур они не попадают.
* Цвет, начертание, выключка, межстрочный интервал и тень берутся оттуда же.
  Подпись части стоит внизу справа — там же, где в зале стоит адрес места
  Писания.

Один слайд — одна часть песни, в порядке пения; перед песней титульный
слайд с названием и автором. Печатный песенник в PDF, наоборот, делается
на белой бумаге: фон там только съел бы тонер.

Самопроверка гоняет круг: экспортирует песню и импортирует обратно — в том числе
презентацию PowerPoint, своим же разбором `.pptx`. Проверяется не экспорт
сам по себе, а то, ради чего он нужен: песня должна выйти из программы
и вернуться целой.

## Каталог песен

Библиотека вкладки «Песни» — это то, что поют сейчас: десяток песен
на ближайшее воскресенье, с поправленным порядком частей и своими фонами.
Каталог — другое: это общий сборник общины, всё, что накопилось за годы.
Держать то и другое в одном списке значит искать сегодняшнюю песню среди
шестисот.

Поэтому каталог живёт отдельно — своим файлом и своим окном поверх программы.
Открывается кнопкой **«каталог»** в заголовке библиотеки песен.

**Вкладки называет община, а не программа.** Изначально их три — «Песни
возрождения», «Песни для детской группы», «Песни для старшей группы», — но
это только начало. Вкладку переименовывают двойным щелчком, добавляют кнопкой
«+ вкладка», убирают и переставляют правой кнопкой. Сколько их и как они
называются, в коде не записано нигде: «Рождественские», «Пасхальные»,
«Авторские», «Молодёжные» — сколько нужно.

Убранная вкладка не уносит песни с собой: они переезжают в соседнюю.
Последнюю вкладку убрать нельзя — песням стало бы негде лежать.

**Песни носят между вкладками мышью.** Взяли песню в списке, бросили
на другую вкладку — она там. Всё, что в песне есть, остаётся при ней:
части, порядок пения, фон, номер, автор.

**Одно название дважды не заводится.** Кладут песню в каталог — программа
сперва смотрит, нет ли уже такой: «В каталоге уже есть песня с таким
названием: „Бог велик"». Второй копии не появляется, и неважно, в какую
вкладку её клали и откуда принесли — с компьютера или из библиотеки.
Название сравнивается по смыслу, а не побуквенно: «Бог велик!» и «бог
ВЕЛИК» — одна и та же песня; «ё» и «е» тоже не различаются.

**Поиск идёт по всему каталогу сразу.** Песню помнят по названию, а не по
тому, в какую вкладку её когда-то положили, — поэтому строка поиска ищет
везде, а у найденного показывается, в какой вкладке оно лежит. Пустая строка
возвращает открытую вкладку.

**Ничего в каталоге нет, пока его не наполнят.** Программа не кладёт туда
ни одной песни сама — чем наполнить сборник общины, решает община. Песни
попадают в него двумя путями: кнопкой «добавить с компьютера» (читаются те же
форматы, что и при обычном импорте, с тем же разбором припева и тем же фоном)
и правой кнопкой по песне в библиотеке — «В каталог».

**Как он выглядит.** Каталог открывают, чтобы искать, поэтому поле поиска
стоит первым и во всю ширину, а рядом с ним счёт: «песен: 48» или «найдено 3
из 48». Вкладки — кружками, у каждой счётчик песен; открытая залита, новая
заводится пунктирной кнопкой рядом. Строка песни: номер в своей колонке
слева, название, а во время поиска ещё и вкладка, в которой песня лежит.
Нажатая строка отмечена полосой слева, и «взять в песни» показывается только
у неё и у строки под курсором: иначе список из сорока песен превращается
в сорок кнопок.

Высота списка задана нарочно. Окно, прыгающее на каждую букву запроса, сбивало
бы глаз, а каталог из трёх песен не должен схлопывать окно в полоску.

**«Взять в песни»** копирует песню из каталога в библиотеку и сразу открывает
её там. Такая песня в библиотеке уже есть — открывается она же, а второй
копии не появляется. В зал из каталога ничего не выводится: каталог — склад,
а не пульт.

## Караоке по голосу

Оператор ведёт караоке рукой: слушает пение и жмёт `Enter` на каждой строке.
Полтора часа подряд, не отвлекаясь ни на что другое, — а ему ещё нужно
смотреть план, готовить следующий пункт и отвечать пастору. Поэтому программа
слушает зал сама.

**Слушает она не язык вообще, а слова именно этой песни.** Общее пение под
синтезатор распознаётся плохо: половина слов смазана, окончания проглочены,
поют протяжно. Но искать-то нужно не «что сказали», а «где мы в песне», —
и это совсем другая задача. Из трёхсот слов открытой песни нужное
вытаскивается уверенно там, где из трёхсот тысяч слов языка не вытащилось бы
ничего. Список слов песни отдаётся распознавателю как грамматика, и он ищет
только среди них.

**Ищем не точное совпадение, а близкое.** Слово считается тем самым, если
отличается на одну-две буквы, и чем оно длиннее, тем больше промахов ему
прощается. Слова короче трёх букв не ищем вовсе: «и», «на», «в» встречаются
везде и не говорят ни о чём.

**И ищем не одно слово, а цепочку последних услышанных.** Одно слово
встречается в песне десять раз, а «свят господь вседержитель» — один. Чтобы
подсветка сдвинулась, совпасть должны два слова подряд; свежим словам —
последним четырём — веры больше, чем сказанным полминуты назад. Вперёд
смотрим на двенадцать слов: пропустить строку певцы могут, а перескочить
через куплет — нет.

**Слайд допет — включается следующий**, если стоит галочка «Переключать
слайды по звуку». Раньше она называлась «Листать слайды самой» — по названию
нельзя было понять ни что она листает, ни отчего.

**Любое действие оператора перехватывает ход сразу.** Переключили слайд
руками — подсветка идёт оттуда, без вопросов и подтверждений: программа
ошибается чаще человека, и спорить с ним ей не о чем.

**Голосовой модуль ставится один раз.** Разбор речи требует обученной
модели — сорок с лишним мегабайт. В программу её не вшиваем: половине общин
голосовое караоке не нужно вовсе, а установщик потяжелел бы в полтора раза.
Кнопка в «Управлении» берёт модуль сперва со своего сайта, а если тот
молчит — прямо у авторов Vosk. В доме молитвы интернета может не быть совсем:
тогда модуль приносят на флешке, и «Взять с диска» кладёт тот же файл на то же
место. Файл меньше двадцати мегабайт модулем быть не может — так отличается
настоящий архив от обрывка загрузки и от страницы с ошибкой, сохранённой под
его именем.

**Рядом с кнопкой видно, что происходит.** Доходит ли звук вообще («тихо
на входе — проверьте кабель и гнездо»), какой вход слушается, и что программа
разбирает прямо сейчас. Без этого «не работает» означает что угодно: нет
модуля, нет микрофона, микрофон есть, но выбран не тот, звук идёт, но песня
не открыта.

**Разбор живёт в отдельном невидимом окне.** Причин три, и каждой хватило бы
одной: он идёт в WebAssembly и требует `unsafe-eval` — давать такое окну,
где живёт вся программа, нельзя; модуль на сорок мегабайт разворачивается
в памяти, и пока он грузится, окно стоит колом — пусть стоит это, а не пульт;
и такое окно можно закрыть и открыть заново, если разбор запутался, не трогая
ничего остального. Само оно ничего не решает: слышит слова и отправляет их
пульту, а где эти слова в песне — считает пульт.

Поэтому и поиск места вынесен в `shared/karaokeMatch.ts` — чистый разбор,
без окон и микрофона. Его проверяет `npm run check`: то, что нельзя проверить
без живого зала, проверить нельзя вовсе, а так проверяется главное.

Прежняя подсветка «по звуку» из версии 0.2.1 убрана. Она отмечала строку
спетой на каждый громкий звук — а в зале, где играет синтезатор, тишины
не бывает, и подсветка уезжала в конец песни на втором куплете.

## Экраны

Кнопка **«Экраны»** в шапке отвечает на один вопрос: куда показывать.
Три строки — три окна вывода, каждое со своим содержимым:

| Строка | Что видно |
|---|---|
| Зал | чистый слайд во весь экран: рамки нет, курсора нет, фон чёрный |
| Сцена | тот же слайд, а рядом часы, таймер служения и что идёт дальше |
| Трансляция | отдельное окно для стрима: его отдают в OBS «захватом окна» |

Роль приходит в адресе окна вывода. Зал и трансляция показывают одно и то же —
разница в том, что это разные окна: захват стрима не должен зависеть от того,
что происходит с проектором. Сцена собрана иначе: там видно то, чего в зале
быть не должно. Проповеднику это позволяет не оборачиваться, музыкантам —
видеть, что дальше. Что «дальше» — во время песни это следующая часть,
а между пунктами служения «Главная» подставляет следующий пункт папки.

**Кнопки экранов — на «Главной», справа от окна слайда.** Столбик кнопок,
по одной на каждый подключённый монитор. Нажали — кадр принял пропорции
этого экрана, и видно, как слайд ляжет именно на нём.

Кнопки стоят в одном месте, а выбор действует на всю программу: и «Окно
слайда», и «Предварительный просмотр», и кадры во вкладках «Библия»,
«Тексты» и «Песни» меняются разом. Экран в зале один, и спрашивать про него
в каждой вкладке заново значило бы четыре раза отвечать на один вопрос.

Кнопок ровно столько, сколько мониторов видит система, и список живой:
подключили проектор посреди служения — кнопка появилась сама; выдернули —
пропала, а предпросмотр переехал на оставшийся экран. Ничего обновлять
руками не нужно и нигде не прописано, сколько их бывает.

Подписаны кнопки разрешением — «1920 × 1080», «3840 × 2160». Не номером:
номера мониторов Windows раздаёт как ей вздумается и меняет их местами после
перезагрузки, а разрешение своего проектора человек знает. Разрешение
берётся настоящее, с поправкой на масштаб Windows: экран 4K при масштабе
150 % система называет 2560 × 1440, но написано на коробке 3840 × 2160 —
и в списке должно стоять оно. Два одинаковых монитора остаются двумя
кнопками: это разные экраны, и различает их вторая строка — «Зал», «Сцена»,
«здесь пульт» или просто «экран 2».

**Зачем это.** Пропорции у экранов разные, и один и тот же стих на них
выглядит по-разному: на широком телевизоре он ложится в три строки,
на старом проекторе 4:3 — в четыре, а на вертикальном экране в фойе —
совсем иначе. Увидеть это лучше за пультом, до служения. Кегль в кадре
подбирается настоящим замером — тем же, что и в зале, — поэтому предпросмотр
не рисует «примерно так», а показывает, как будет.

При первом запуске выбран экран зала, а если вывод ещё никуда не открыт —
основной монитор. Выбор общий для всех вкладок: экран один и тот же,
и предпросмотр везде должен показывать одно и то же.

**Окно вывода рядом с пультом открывается за ним.** На своём мониторе такое
окно ничего нового не показывает — то же самое видно в предпросмотре, — и
нужно оно разве что для захвата в трансляцию. Поэтому оно открывается, но
не поверх работы: сразу после показа пульт поднимается обратно наверх.
Поднять окно можно из панели задач, свернуть и закрыть — как любое другое.
На проекторе окно, наоборот, никуда не убирается: оно там одно.

**Курсор прячется только там, где окно и есть проектор.** В зале стрелка
посреди слайда осталась бы на экране всю проповедь. А окно рядом с пультом —
обычное окно: его двигают, тыкают и закрывают крестиком, и без курсора это
вслепую. Окно вывода узнаёт о себе из своего же адреса — `?windowed=true`.

**Заголовок окну ставит программа, а не страница.** Страница вывода одна
на все три окна, и заголовок в ней один и тот же; а в панели задач их надо
различать — зал, сцена, трансляция.

**Когда монитор один, выбирать не из чего** — в строке стоит кнопка
«Включить». Вывод открывается обычным окном рядом с пультом; так готовят
служение дома, где второго экрана нет.

**На экране, где сидит оператор, вывод никогда не разворачивается во весь
экран.** Иначе чёрное окно накрывает пульт, и сделать нельзя уже ничего:
ни показать стих, ни вернуться назад, ни закрыть само окно — кнопок у него
нет. Правило одно на все случаи: и когда монитор один, и когда оператор
промахнулся мышью по своему экрану при подключённом проекторе.

**Мониторы приходят и уходят прямо во время служения:**

| Что случилось | Что делает программа |
|---|---|
| Подключили проектор | вывод, сидевший окном у пульта, уезжает на него и разворачивается |
| Выдернули проектор | вывод возвращается к пульту обычным окном — его видно и можно закрыть |
| Свободных экранов меньше, чем выводов | первым занимает проектор зал: он важнее сцены |
| Экран уже занят другим выводом | туда ничего не переносится: зал поверх сцены — не помощь |

Windows сообщает о новом мониторе несколько раз подряд, пока проектор
просыпается. Поэтому переезд откладывается на полсекунды: иначе окно
пересоздавалось бы на каждое сообщение и мигало чёрным на весь зал.

**Назначение запоминается.** Закрыли программу с залом на проекторе —
в следующий раз он откроется там же сам. Восстанавливается только вывод
на чужом мониторе: дома, где экран один, окно вывода само выскакивать
не должно — программу открывают и просто чтобы добавить песню. Если Windows
успела перенумеровать мониторы, а чужой экран ровно один, вывод уходит на
него: почти наверняка это тот же проектор с новым номером.

Решения — какой монитор чей, что куда переносить, что открывать при запуске —
вынесены в [`src/shared/screens.ts`](src/shared/screens.ts) отдельно от самих
окон. Проверять это руками нужно с проектором в руках, а ошибка здесь стоит
дороже прочих: она отбирает у оператора управление посреди служения. В таком
виде всё это проверяется самопроверкой.

**Проектор не моргает между слайдами.** Слайд презентации — это файл
на диске, и открывается он не мгновенно. Меняя картинку фона, Chromium красит
место фоновым цветом, пока она не разжата, — и между слайдами проскакивал
чёрный кадр: листаешь проповедь, а экран моргает на каждом слайде.

Поэтому новое состояние доходит до окна зала не сразу: сперва картинку
разжимают в память, и только потом отдают на отрисовку. Подмена проходит
в один кадр, и моргать нечему. Ждём не дольше четверти секунды — не открылась
за это время, лучше моргнуть, чем держать в зале прошлый слайд, пока оператор
недоумевает, почему кнопка не сработала.

Ждём только смену самой картинки. Чёрный экран, закраска караоке, нижняя
плашка идут как раньше, без задержки: у них картинка та же.

| Дерево папок | `%APPDATA%/visiologos/tree.json` |

Настройки пишутся через главный процесс, а не в `localStorage` окна: под
`file://` хранилище браузера не переживает даже перезагрузку страницы, и план
служения терялся бы вместе с ней. Запись атомарная — сначала во временный файл,
потом переименование, поэтому выключенный посреди сохранения свет не оставит
обрезанный JSON.

## Модули переводов

Поддерживается формат BibleQuote («Цитата из Библии»): папка с `bibleqt.ini`
и файлами глав. Кодировка определяется сама — и UTF-8, и CP1251.

Метки глав и стихов берутся из `ChapterSign` и `VerseSign` по общему правилу:
это строка, после которой идёт номер. Обычно это тег (`<strong>3</strong>`),
но старые модули помечают главы якорем — `ChapterSign = A NAME`, а в тексте
стоит `<A NAME="glava1">`. Поэтому парсер ищет метку как есть и берёт первое
число после неё, а не пытается угадать закрывающий тег.

Модуль, в котором не нашлось ни одного стиха, не попадает в список: иначе
оператор выбрал бы его на служении и увидел пустые колонки.

Флагу `Apocrypha` в ini доверять нельзя — в «современной редакции»
Синодального он стоит `N`, хотя одиннадцать неканонических книг там есть.
Неканонические определяются по названиям и по приставке «(неканон.)»,
которая затем убирается из имени книги.

Модули из папки `modules/` переносятся в хранилище при первом запуске. Кнопка
«+ Перевод» во вкладке «Библия» добавляет модуль из любой папки на диске.

Из модуля берутся: названия и сокращения книг (на них же работает разбор
адресов и деление на разделы), номера глав и стихов, слова Иисуса `<j>`
и слова переводчиков `<t>`. Номера Стронга вырезаются — на слайде они не нужны.

Одна поправка вносится при загрузке. По смыслу формата `<t>` помечает слова,
добавленные переводчиками, и их набирают курсивом. Но модули помечают им ещё
и поэзию: в Синодальном так обёрнуты 7789 стихов целиком, включая 2525 из 2526
стихов Псалтири. Если верить тегу буквально, вся Псалтирь уедет на проектор
курсивом. Поэтому курсив остаётся только там, где `<t>` выделяет часть стиха,
а не весь стих. На диске модуль при этом не меняется.

**Свой формат перевода: один файл `.vlb`.** BibleQuote — это папка с сотней
файлов глав, и передать её другой церкви или перенести на второй компьютер
непросто: архив, распаковка, «а куда это класть». `.vlb` — один файл,
разобранный перевод, упакованный целиком. Он ставится мгновенно, потому что
разбирать в нём уже нечего, и его можно просто бросить в окно программы.
Выгружается любой перевод, откуда бы он ни пришёл, — кнопкой в «Библии».

**Переводы с русскими названиями больше не затирают друг друга.** Имя файла
на диске делалось из названия перевода, а всё, что не латиница, из него
выбрасывалось: «Введение» и «Евангелизм» превращались в одно и то же
`_________`, и второй перевод молча стирал первый. Теперь из имени убирается
только то, что и правда запрещено в имени файла Windows, — буквы, любые,
остаются. Переводы, добавленные прежними версиями, читаются по старому имени:
перекачивать ничего не нужно.

```
      RemoteBox.tsx    окошко «Пульт проповедника»: кнопки и что подключено
      CatalogBox.tsx   окно каталога песен поверх программы
resources/
  icon.png         значок программы: окно, шапка, «О программе»
  icon.ico         он же для установщика и .exe, все размеры от 16 до 256
  icon-source.webp исходник без скругления

  selfcheck.ts     самопроверка парсеров: `npm run check`
  proPresenterFixtures.ts файлы ProPresenter, собираемые на лету

```

Кегль в слайдах задаётся в долях от высоты слайда, а не в пикселях, поэтому
маленькое окошко предпросмотра выглядит точно так же, как экран в зале.

## Чего ещё нет

По «Главной» не сделаны: экспорт и импорт служения одним файлом, умные папки
(«Недавние», «Топ месяца», «Давно не пели»), история версий песен
и «закрепление» проведённого служения, предупреждение при правке песни,
которую используют несколько папок (число рядом с пунктом уже показывается,
предупреждения при сохранении нет).

По песням не сделан отчёт по лицензии за период: данные копятся (сколько
раз пели и когда), самого отчёта нет. Импорт из PDF берёт только текст —
картинки и сканы он прочитать не может и честно об этом говорит.

По караоке по голосу: слушает программа только по-русски — модуль на другом
языке ставится тем же способом, но выбрать его в «Управлении» пока нельзя.
Пение на два голоса и разложение по партиям она не различает.

По пульту проповедника: клавиши закреплены за кнопками намертво, назначить
свои нельзя. Список устройств — подсказка, а не ответ: половина пультов
представляется Windows как «USB-устройство ввода», и отличить их от мыши
она не даёт.

Общее, чего ещё нет: языков пока два — русский и английский; оформление
для трансляции (окно открывается, но показывает то же, что зал), пульт
на телефоне, настраиваемые клавиши, автосохранение места в служении, режим
низкой нагрузки.
